# Auth and admin look like two different places: an Access shell and an Account page

**Initiatives:** [dms_tessera_default_theme](../../../../../planning/initiatives/dms_tessera_default_theme.md) · **Status:** blocked:decision · **Created by:** ssangdod@albany.edu · **Edited by:** —

**Project:** DMS library (`src/dms` submodule) · **Topic:** patterns/auth, patterns/admin

## Objective

Make the auth pattern's management pages look and feel like a separate place from site admin. This is UI/UX
work: no route, API or permission changes.

Today the auth pattern's **Users, Groups, Profile and Access log** pages render inside `AdminLayout`
(`patterns/auth/siteConfig.jsx`). They get the admin SideNav (Sites · Themes · Tenants/Domains · Auth ▾), an
`admin /` breadcrumb and the admin badge. The admin pattern's own SideNav carries the same "Auth" sub-menu
(`patterns/admin/siteConfig.jsx` ~419–480). So:

- an author can't tell when they've left site-building for people management;
- a plain signed-in user's **Profile** looks like an admin tool, inside an "Auth" sub-menu next to Sites and
  Themes;
- the same menu is built twice, in two patterns (`buildMenuItems` in auth, `getMenuItems` in admin), and has to
  be kept in step by hand.

## Design: three rooms

Mockups (tessera v6 design system, open through the floating nav widget):

| Mockup | What it shows |
|---|---|
| `src/themes/tessera/design_system_v6/pages/auth-admin-split.html` | Overview: the three rooms, the cues that tell them apart, admin SideNav before/after, routes, open questions |
| `.../pages/access-users.html` | Access shell: Users |
| `.../pages/access-groups.html` | Access shell: Groups (+ "where permissions live" note linking to a pattern's Access tab) |
| `.../pages/access-log.html` | Access shell: Access log (filters and columns as `authAccessLog.jsx`) |
| `.../pages/account-profile.html` | Account page (Profile) |

Generated by `design_system_v6/scripts/access_split.py` (registered in `build_all.py`), except the hand-written
overview. Checked at 1280px light/dark and 390px: no horizontal scroll.

1. **Site admin** (admin pattern). It stays as it is, minus the "Auth" sub-menu. One exit row at the foot of the
   SideNav: *access ↗*, shown only to users with `auth-users` or `auth-groups`.
2. **Access** (auth pattern: `/manage/users`, `/manage/groups`, `/manage/access-log`). A new shell:
   - a board (dark) top band in both modes, with a marker-yellow keyline so it stays distinct in dark mode;
   - a key mark, the title "Access", a "who can do what" badge and a site chip;
   - **tabs** (users · groups · access log, with counts) instead of a SideNav;
   - one exit, *site admin ↗*, shown only to users with a site verb;
   - the user's avatar links to Account.
   The tables, modals and actions are the same as today's (no lost features).
3. **Account** (auth pattern: `/manage/profile`). A narrow (measure, 640px) personal page with no admin chrome:
   - "← back to `<site>`", email, reset password and sign out;
   - a *manage access ↗* link for those allowed;
   - reached from the user menu ("Account") on every page.
   - *Proposed:* a read-only "your groups on this site" list (`user.groups` is already on the client).

Login, signup, and the forgot/reset password pages keep `AuthLayout` (`login.html`). They are already separate.

## Proposed changes (after approval)

1. **`AccessLayout`** in `auth/siteConfig.jsx` (or `auth/components/AccessLayout.jsx`). It replaces
   `AdminLayout` for users/groups/access-log. It renders through `UI.Layout` with a new named style
   (`activeStyle='access'`) rather than raw markup, following the activeStyle-only rule for UI controls.
   Tabs come from the UI `Tabs` component; the items are the existing permission-gated entries minus Sites/
   Themes/Tenants/Domains/Profile.
2. **`AccountLayout`** for `profile`: a bare centered wrapper like `AuthLayout`'s bare path, plus the
   back-to-site link. It is not gated on any site verb, as today.
3. **Theme keys:** `auth.authPages.access.*` and `auth.authPages.account.*` in `auth/defaultTheme.js`, with the
   tessera_v6 values taken from the mockups. If the owner chooses fallback, read the old
   `manage.*` keys when the new ones are unset.
4. **Admin pattern:** drop the "Auth" sub-menu from `admin/siteConfig.jsx`. Add the gated *access ↗* exit row.
5. **User menu:** add "Account" (→ `/manage/profile`) for every signed-in user. "Manage access" for those with
   `auth-users`/`auth-groups`.
6. **Profile copy:** follow the tool register (`src/dms/skills/writing-site-copy.md`, `src/dms/voice/`).
7. **Mockup sync:** mirror any implementation change back into the mockups. Update `admin-users.html`,
   `admin-groups.html` and `admin-profile.html` to point at the new pages, or retire them.

Out of scope: routes (`/manage/*` stays, so bookmarks and email links keep working), permissions, the auth
API, and login/signup/password pages.
